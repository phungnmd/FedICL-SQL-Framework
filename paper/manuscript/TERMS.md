# Terms and notation

This document establishes the terminology and the notation of the
manuscript. Each defined concept retains its designated term from its
first occurrence to its last. The terms conform to the established usage
of the field. Approved by the owner on 2026-11-26; the component names
were added on 2026-11-27.

The table designates terms for the concepts it defines and imposes no
further restriction. General vocabulary remains available wherever it
cannot be confused with a defined concept (the output of the model, the
running time, the answer to a research question). Nominal compounds of
the field are admissible alongside the defined terms: "client databases"
for the databases of a client, "client-side" for what a client performs
locally. The third column records only the laboratory labels that a
defined term supersedes.

## Terms

| Term | Meaning | Replaces |
|---|---|---|
| `\method` (FedLS-SQL) | the proposed framework. The paper names it "a federated learning framework for Text-to-SQL" where it introduces it (abstract, Section 1 and its contribution list, Section 3.2, Section 8; owner, 2026-11-27); elsewhere it is `\method` or "the method", and the rows of the tables stay "federated methods" | |
| the model | the trained model: Qwen2.5-Coder-1.5B-Instruct with a LoRA adapter unless another model is named | the student |
| the pretrained model | the model before any round; "No training" as the label of its row | the base student |
| FedAvg SFT | supervised fine-tuning (SFT) on the gold SQL queries with federated averaging; the main baseline | |
| FedDPO | federated DPO as published in OpenFedLLM: pairs constructed once, one reference model for all rounds, no NLL term | |
| supervised warm-up | the component consisting of the $T_w$ warm-up rounds (Section 3.3) | |
| warm-up round | a FedAvg SFT round of the method ($T_w$ of them) | SFT stage |
| preference round | a round of sampling, execution-based labeling, pair construction and local training with the preference and NLL terms | DPO round |
| gold SQL query, gold SQL | the reference query of a training or evaluation question | |
| sample (noun) | a SQL query drawn from the model for a training question at temperature 1 ($N$ per question) | |
| prediction | the SQL query the model generates for an evaluation question | |
| generate | the model generates a query | |
| sample (verb) | a client samples $N$ queries from the model | |
| execute, execution | a query is executed on a database; a query that cannot be executed "fails to execute" | |
| execution result | what a query returns on a database, $\mathrm{exec}(y, d)$ | |
| execution label | correct: the execution result of the sample equals that of the gold SQL query on the client's database; incorrect: otherwise | right, wrong |
| execution error | what an incorrect query raises when it fails to execute or exceeds the time limit; also the name of that kind of incorrect query | |
| incorrect result | an incorrect query that executes and returns a different result | wrong result |
| client-side execution labeling | the component in which a client samples queries from the current global model and assigns each an execution label by executing it on its own databases (Section 3.4) | |
| execution-derived supervision | the training signal that execution labels provide, as distinct from the gold SQL query alone | |
| preference pair | a correct and an incorrect sample of the same question, both generated by the model ($M$ per question) | |
| on-policy pair construction | the component that constructs the preference pairs of a round from that round's labeled samples (Section 3.5) | |
| reference model | the model against which the preference term measures the change: the global model at the start of the round | |
| on-policy pairs | pairs constructed anew in each preference round, from samples of that round's global model | |
| preference objective | the loss of a preference round: the preference term plus the weighted NLL term (Section 3.6) | |
| the preference term, the NLL term | the two terms of the preference objective; the preference term is the DPO loss | |
| client, server, global model, local training, round, aggregation, adapter | as usual in federated learning | arm, line |
| EX, TS | execution accuracy, test-suite accuracy | |
| BIRD dev, Spider test, Spider dev, Spider-Syn, Spider-Realistic, Spider-DK | the evaluation sets | |

Abbreviations given in full at first use: SFT, FedAvg, DPO, NLL, LoRA,
EX, TS, non-IID.

## Notation

Defined in Section 3.1 of the paper and used unchanged afterwards.

| Symbol | Meaning |
|---|---|
| $K$, $k$ | number of clients, a client |
| $\mathcal{D}_k$ | the training set of client $k$; an element is $(q, d, y^\star)$: question, database, gold SQL query |
| $n_k$ | number of questions of client $k$ |
| $x$ | the prompt constructed from $q$ and the schema of $d$; the same prompt in training, sampling and evaluation |
| $T$, $T_w$ | total number of rounds, number of warm-up rounds; rounds $T_w + 1, \dots, T$ are preference rounds |
| $\theta^{t}$, $\theta_k^{t}$ | the global adapter after round $t$; the adapter of client $k$ after local training in round $t$ |
| $\pi_{\theta}$ | the model with adapter $\theta$ |
| $N$, $M$ | samples per question, preference pairs per question |
| $\mathrm{exec}(y, d)$ | the execution result of query $y$ on database $d$ |
| $y^{+}$, $y^{-}$ | the correct and the incorrect sample of a preference pair |
| $\mathcal{P}_k^{t}$ | the preference pairs of client $k$ in round $t$ |
| $\beta$, $\lambda$ | the scale of the preference term, the weight of the NLL term |
